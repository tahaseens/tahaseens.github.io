The problem

Important decisions are often hardest to understand before they are final.

Local governments make consequential decisions involving land use, public revenue, infrastructure, procurement, community services, and surveillance technologies. The relevant information may be buried in long agendas, technical staff reports, procurement files, and public notices.

Institutional stakeholders often have dedicated resources for following these processes. Individual residents may only discover a proposal after a hearing, contract award, or vote. PublicBrief is designed to reduce that information imbalance without advocating for a political position.

  1. Find relevant local issues.
  2. Understand the proposal and current status.
  3. Separate documented facts from possible implications.
  4. Identify who holds each decision-making role.
  5. See what remains unanswered or unclear.
  6. Find appropriate participation routes.
  7. Prepare useful questions or public comments.
How it works

From a difficult source document to an informed next step.

The locality feed is selective and manually curated from official sources. It is not a live scraper or a complete record of every government agenda.

01 Scan a locality

Browse selectively curated issues linked to official government agendas, staff reports, procurement postings, budgets, laws, and program pages.

02 Analyze a document

Paste agenda, notice, resolution, or staff-report text to receive a structured brief grounded only in the submitted material.

03 Move toward action

Review decision roles, participation opportunities, unresolved questions, official contacts, and a ready-to-edit public-comment draft.

Responsible AI

The model assists with structure; the source remains the authority.

PublicBrief constrains document analysis to the material a resident submits and makes uncertainty visible instead of filling gaps with invented detail.

  • Uses only the submitted document as evidence.
  • Treats pasted content as untrusted source material and ignores embedded instructions.
  • Separates documented facts from potential implications.
  • Identifies missing information rather than inventing it.
  • Shows short source excerpts near significant findings.
  • Does not recommend a political position or provide legal advice.
  • Validates requests and structured responses on the server.
  • Renders generated content as text, never arbitrary HTML.
  • Uses curated application data for actionable official links.
  • Reminds residents to verify details with the issuing government body.
Data-use note. Submitted text is processed by the configured AI provider. Users are warned not to submit sensitive personal information. PublicBrief does not claim zero provider retention or guarantee that an AI-generated brief is complete.
Technology

A small application with deliberate boundaries.

Implementation

  • Next.js App Router, React, and TypeScript
  • Tailwind CSS and responsive interface design
  • OpenAI Responses API with structured model output
  • Zod request and response validation
  • Server-side API route and Vercel deployment
  • ESLint, TypeScript checking, automated security tests, and production build verification

Security and reliability

  • The API key remains server-side and is never exposed to the browser.
  • Input-size limits, per-IP prototype rate limiting, and hard request timeouts control misuse and cost.
  • Malformed requests and invalid model responses fail with controlled errors.
  • Prompt-injection defenses delimit documents as evidence rather than instructions.
  • API responses use no-store caching, and the app sends restrictive security headers.
Tool usage. OpenAI tools assisted with implementation and structured document analysis. Product direction, source selection, editorial decisions, and deployment remain under human review.
Current scope

Deployed functionality, with prototype limits stated plainly.

Available now

  • Loudoun County and Fairfax County locality views
  • Selective, manually reviewed issue feeds linked to official sources
  • Manual analysis of pasted government text
  • Structured briefs, evidence excerpts, questions, contacts, and public-comment drafts
  • Manual district selection with official directory links

Not implemented

  • Complete or continuous government-agenda monitoring
  • Automatic representative matching or address collection
  • User accounts, authentication, or a database
  • PDF upload, URL parsing, or automatic PDF extraction
  • Automatic email sending, saved briefs, or notifications
  • Guaranteed AI accuracy; results still require official verification
Future direction
